Sección 3 — Mapa Intrínseco de Memoria

  • memory.db Schema Completo:
    • events (id TEXT PK, ts TEXT, source TEXT, type TEXT, project TEXT, app TEXT, window_title TEXT, category TEXT, monetizable INT, risk TEXT, duration_seconds INT, payload TEXT) — Índices en ts, type, project. Escritores: atlas_activity.py (inbox), memory_event_ingest. Lectores: atlas_foco, atlas_web_server.
    • sessions (id TEXT PK, project TEXT, started TEXT, ended TEXT, status TEXT, summary TEXT, notes_count INT) — Índice en status. Escritores: session_start, session_end. Lectores: memory_summary, atlas_web_server.
    • notes_index (id TEXT PK, path TEXT, title TEXT, type TEXT, project TEXT, tags TEXT, created TEXT, status TEXT, links TEXT, summary TEXT) — Escritores: note_save. Lectores: note_search, summary.
    • preferences (key TEXT PK, value TEXT, scope TEXT, project TEXT, updated TEXT) — Escritores: pref_set. Lectores: pref_get, summary.
    • graph_nodes / graph_edges — Grafo de conocimiento derivado de notas Markdown.
    • notes_fts — Tabla virtual FTS5 para búsqueda full-text de notas.
  • vault/ Árbol completo:
    • global/: Preferencias (identity.md, programas.md, style_profile.md), decisiones, facts, sesiones, tasks.
    • /: MEMORY.md (índice ligero ~30 líneas), carpetas notes/, decisions/, facts/, sessions/, graph.json.
    • outputs/: Informes publicados (REQ-C8).
  • state/: Contiene daemon.heartbeat, foco_rules.json, guardian.json, model_capabilities.json, reports_index.json, routing_log.json, search.json, secret_rotation.json, supervisor_cooldown.json, usage_log.json, friction_log.jsonl. Si falta alguno, se regenera con defaults o falla componente dependiente.
  • inbox/: Cola temporal de eventos .jsonl. Si se acumula (>20), atlas_health alerta amarilla.
  • backups/: Dos esquemas:
    • ZIP plano (atlas_YYYYMMDD_HHMMSS.zip) via mcp_memory_server.py --cli backup: vault + state/memory.db*; retención 14.
    • AGE cifrado (atlas_backup_YYYYMMDD_HHMMSS.tar.gz.age) via atlas_backup_encrypted.py backup --recipient age1…: tarball gzip + age; retención 14; requiere clave privada para restaurar.

Sección 4 — Sesiones y Flujos (6 flujos con ✖)

  1. A. Logon de Windows: Task Scheduler lanza AtlasActivity, AtlasSupervisor, AtlasBootCheck. ✖ Conflicto .venv bloqueado al arranque simultáneo.
  2. B. Turno de Chat: atlas_chat.py → opencode serve (4096) → pywebview overlay con progress/ETA (P-1). ✖ WebView2 ausente o puerto ocupado.
  3. C. Tarea C2 (Cierre Forzoso): crear_contrato → bucle turno/verificador/crítico → cierre/escalada. ✖ Criterio mal configurado → bucle hasta max_intentos.
  4. D. Captura Daemon (10s): atlas_activity.py → Win32 API → inbox/ → cada 5m event_ingest → SQLite. ✖ Escritura inbox bloqueada por permisos.
  5. E. Backup Diario: Tarea AtlasBackup (03:00) ejecuta atlas_backup_encrypted.py → age → retención 14. Tarea AtlasBackupZip (03:30) ejecuta mcp_memory_server backup → zip. ✖ Clave age faltante → backup cifrado falla silenciosamente; zip sin cifrado pasa.
  6. F. Evaluaciones (Evals): Tarea AtlasEval (lunes 03:30) ejecuta atlas_eval.py → genera state/evals/YYYY-MM.json → publica informe (REQ-C8). ✖ Datos insuficientes → eval vacío sin alerta.

Sección 10 — Lo que el Sistema NO Hace

  • No envía datos, telemetría ni contenidos de la bóveda a servidores remotos de terceros (arquitectura 100% local-first).
  • No ejecuta acciones destructivas de archivos fuera de los directorios permitidos definidos en el Guardián.
  • No realiza predicciones financieras ni operaciones de trading autónomas.
  • No modifica configuraciones del sistema operativo (Registro de Windows) sin confirmación estricta en niveles guard / strict.
  • No autentica endpoints HTTP locales (solo localhost).
  • No rota claves automáticamente; solo avisa (secret_reminder).
  • No reinicia controller C2 caído (demand=True) – requiere intervención manual.
