# Verificación Dashboard v3 — FIX (Gate VIS-001)

## §16 — Evidencia Post-Reinicio con Datos Reales

### Causa Raíz del Fallo Anterior

El dashboard servía `dashboard_v3.html` (por `UI_V3=1` en `ui_config.json`), pero se editaba `dashboard.html`. Resultado: **todos los cambios nunca llegaban al navegador**.

Además, el JS de `dashboard_v3.html` tenía errores fatales:
1. `$o-btn` / `$o_input` — syntax error que mataba toda la IIFE
2. `AbortSignal.timeout()` — no soportado en todas las versiones de Chromium
3. `vis-network` + `algorithmic_art.js` — scripts externos cargados 2 veces
4. `const STATUS` declarado 2 veces — SyntaxError
5. `hc.replace('rgb','rgba')` — fallaba porque `hc` era hex, no rgb

### Correcciones Aplicadas

| # | Fix | Detalle |
|---|-----|---------|
| 1 | **Archivo correcto** | Se editó `dashboard_v3.html` (el que sirve el daemon) |
| 2 | **IIFE auto-contenida** | `(function(){...})()` — sin dependencias externas |
| 3 | **Reloj ANTES de fetch** | `tickClock()` corre al arrancar, no espera datos |
| 4 | **Canvas init robusto** | `canvasSize()` con retry 500ms si width=0 + `ResizeObserver` |
| 5 | **try/catch por panel** | 9 paneles independientes — fallo de 1 no mata los demás |
| 6 | **window.onerror visible** | Badge rojo "JS: ..." visible en pantalla, no solo consola |
| 7 | **window.unhandledrejection** | Captura promises rechazadas |
| 8 | **Hex colors correctos** | `ST[hash]` directo en vez de `hc.replace('rgb','rgba')` |
| 9 | **Sin scripts externos** | Canvas HUD inline, 0 dependencias CDN |
| 10 | **AbortSignal seguro** | `typeof AbortSignal !== 'undefined'` check antes de usar |
