01 · Diagrama de fases

F1 · CORE — Memory Core🟢 Estable
  • Entregables: mcp_memory_server.py · state/memory.db · vault/ (global + proyectos) · skill memory · git hook → inbox/ · opencode.jsonc · identity.md (Atlas) · [v1.1] backup diario + script de restore
  • [v1.1] Gates de salida: 10 tools OK · escritura concurrente sin corrupción · memory_session_recover OK · restore de backup OK · el server solo escribe dentro de vault/ · secretos redactados
  • Traspasa a F2: tabla events (app, window_title, category, monetizable, duration_seconds, project) sin migraciones · skill listo para cualquier UI
F2 · ACTIVIDAD — Activity Tracker + Atlas UI🟡 Débil
  • Entregables: daemon background · captura ventana activa ~10s · chat flotante (Opción A: web → opencode serve SDK 1.18.1) · dashboard base · notificaciones · [v1.1] bandeja con estado 🟢/🟡/🔴 + pausa · [v1.1] wrapper fino api.js entre UI y opencode serve
  • [v1.1] Gates de salida: captura sin ralentizar · pausa detiene captura <1s · daemon sobrevive reboot (Task Scheduler + watchdog) · heartbeat visible en memory_health · retención: crudos 90 días, agregados para siempre
  • Traspasa a F3/F4/F5: eventos continuos + tiempo por app. Migrable a B (nativa Win+Alt+M) / C (terminal) sin reescribir backend: solo cambia el contenedor de api.js.
F3 · FOCO — Anti-distracción🟡 Débil
  • Entregables: clasificación monetizable/distracción · avisos · modos de disciplina · reglas en activity_rules.json editable
  • [v1.1] Gates de salida: umbrales ajustables sin tocar código · presupuesto de avisos ≤3/día configurable · override manual siempre disponible
  • Traspasa a F4: métrica "tiempo productivo vs fugado"
F4 · DINERO — Money + Content Engines🔴 Riesgoso
  • Entregables: radar de oportunidades · métricas $ · motor de contenido · dashboard financiero · adaptador CSV (banco/Stripe) + entrada manual rápida
  • [v1.1] Gates de salida: métricas coinciden con eventos crudos · import CSV funciona · toda oportunidad pasa validación humana antes de ejecutar · solo APIs oficiales donde existan
F5 · TUTOR — Trading Tutor (demo)🔴 Riesgoso
  • Entregables: journal demo · checklist · adaptador CSV TradingView → normalizado · tutor de estrategias · análisis de entradas/salidas
  • [v1.1] Gates de salida: 10 trades demo registrados con análisis · checklist bloquea sin confirmación · tutor explica estrategias con datos · nunca dinero real en esta fase
[v1.1] F6 · HORIZONTE — Automatización⚪ Sin compromiso
  • Pipelines, publicación programada, reportes auto. Solo entra si F4/F5 producen procesos repetibles. Nadie mete automatización dentro de F4.

03 · Puntos donde puede romperse

🔴 Pérdida de bóveda/DB sin recuperación [v1.1] · F1Mitigación: backup diario automático a carpeta separada o repo Git privado + gate "restore funciona" antes de cerrar F1.
🔴 Daemon muere: reboot, antivirus, crash [v1.1] · F2Mitigación: Task Scheduler al arranque + watchdog + heartbeat en memory_health; perfil de CPU bajo para no disparar antivirus.
🟡 memory.db crece sin control [v1.1] · F2Mitigación: retención 90 días de crudos, agregados eternos; memory_gc periódico.
🟡 opencode serve cambia o falla [v1.1] · F2Mitigación: wrapper api.js; cambios de versión o migración B/C solo tocan el wrapper, nunca la lógica.
🔴 ToS de redes + oportunidades alucinadas [v1.1] · F4Mitigación: APIs oficiales donde existan; validación humana obligatoria antes de ejecutar cualquier oportunidad.
🔴 Integración TradingView frágil · F5Mitigación: adaptador import CSV → normalizado. Nunca scraping como núcleo.
🟡 Ingresos dependen de que tú los alimentes · F4Mitigación: CSV + entrada manual rápida; el agente lo pide proactivamente.
🟡 Falsos positivos al clasificar distracciones · F3Mitigación: umbrales y reglas en activity_rules.json editable + presupuesto ≤3 avisos/día.
🟡 Post-commit hook falla silencioso · F1Mitigación: hook solo escribe en inbox/; memory_event_ingest drena; memory_health detecta backlog.
🟡 Sesiones huérfanas · F1Mitigación: memory_session_recover al iniciar marca incompletas.
🟡 Bóveda satura el contexto · F1Mitigación: MEMORY.md = índice · memory_gc · summary con presupuesto de tokens.

04 · Reglas anti-ruptura

  • F1 nunca se replantea al llegar a F5 — schema, bóveda, permisos e identidad nacen "finales".
  • Toda integración externa = adaptador reemplazable, nunca lógica en el núcleo.
  • Graphify siempre opcional.
  • Lo que no está en la bóveda no existe.
  • [v1.1] Presupuesto de avisos configurable; si molesta, se ajusta el presupuesto, no se apaga el agente.
  • [v1.1] Backup diario innegociable desde F1.
  • [v1.1] F6 solo existe si F4/F5 demuestran procesos repetibles.
